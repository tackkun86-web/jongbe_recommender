# 종베종목(종가베팅) 데이터 이상 검증 완료 보고서

**검증 일자:** 2026-08-14
**검증 방식:** 코드 수정 후, Naver Finance 실거래 데이터를 직접 fetch하여 원본 HTML 컬럼과 파서 결과를 대조

---

## 1. 발견 및 수정된 이상 (Root Cause)

| 항목 | 내용 |
|---|---|
| **증상** | `get_top_gainers`(상승률 상위, 종베 후보군의 소스)가 `sise_quant.naver`용 파서(`_parse_quant_table`)를 `sise_rise.naver` 페이지에 재사용 |
| **근본 원인** | `sise_rise.naver`는 거래대금/시가총액 컬럼이 없는 다른 레이아웃인데, 기존 코드가 포지셔널 인덱스로 읽어 **매수호가(td[6])를 거래대금으로 오독** |
| **수정** | `_parse_rise_table` 신규 작성(실제 컬럼: N/종목명/현재가/전일비/등락률/거래량/매수호가/매도호가/매수잔량/매도잔량/PER/ROE), `trade_value_eok`는 `가격×거래량`으로 직접 계산, `market_cap_eok`는 `None` 반환 |
| **부수 조치** | `recommender.py`에 `_resolve_market_cap_eok` 추가 — 거래대금 리스트에서 온 종목은 기존 값 사용, 상승률 리스트 전용 종목은 `get_stock_summary`로 실시간 조회 |
| **커밋** | `57dd7e3` |

---

## 2. 실거래 데이터 재검증 범위 및 결과

| 검증 대상 | 방법 | 결과 |
|---|---|---|
| **KOSPI** 거래대금 상위 | raw td 덤프 vs 파서 결과 대조 | 컬럼 매핑 일치, 가격×거래량 ≈ 실제 거래대금 검산 통과 (이상 거래량으로 보였던 저가 ETN도 실제값 확인) |
| **KOSPI** 상승률 상위(수정 파서) | raw td 덤프 vs 파서 결과 대조 | 매수호가 오독 재발 없음, 컬럼 순서 주석과 실측 일치 |
| **KOSDAQ** 거래대금/상승률 상위 | 동일 방식 | KOSPI와 동일 레이아웃, 이상 없음. 거래대금·상승률 양쪽에 중복 등장하는 종목은 `seen.setdefault`로 정확한 거래대금 리스트 값을 우선 채택함을 확인 |
| **시장지수** (`get_market_index`, KOSPI/KOSDAQ) | 실제 값과 비교 | 정상 (KOSPI 6977.94 +2.42%, KOSDAQ 864.65 +0.38%) |
| **일봉(기간) 데이터** (`get_stock_daily_data`) | 삼성전자 10일치 raw vs 파싱 결과 | 컬럼 순서(날짜/종가/전일비/시가/고가/저가/거래량) 일치, 이상 없음 |
| **외국인/기관 순매매(기간) 데이터** (`get_investor_data`) | 헤더 원문 확인 + 5일치 raw 대조 | 기관/외국인 컬럼 순서(td[5]=기관, td[6]=외국인) 실측으로 재확인, 코드와 일치 |
| **후보군 통합 파이프라인** (`_build_candidate_universe` + `_resolve_market_cap_eok`) | 실제 2,386종목 유니버스 실행 | 상승률 전용 2,207종목의 시가총액 폴백 조회 결과가 상식적 범위로 정상 반환 |
| **전체 테스트 스위트** | `pytest -q` | 97개 전체 통과 |

---

## 3. 결론

- **근본 원인 수정 완료 및 검증됨**: 매수호가→거래대금 오독 버그, 실거래 데이터 기준으로 재발하지 않음을 확인.
- **KOSPI/KOSDAQ 양 시장, 당일 시세·기간(일봉/수급) 데이터 전 영역에서 추가 이상 없음.**
- 추가 코드 변경 불필요. 현재 로컬 커밋(`57dd7e3`)이 최종 상태.
